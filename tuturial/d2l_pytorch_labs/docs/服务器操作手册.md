## 1. 连接服务器

### 1.1 三种连接方式

| 方式 | 操作 | 说明 |
|---|---|---|
| VS Code | `Ctrl+Shift+P` → `Remote-SSH: Connect to Host...` → **`amax`** | 推荐，能直接看图、编辑代码 |
| PowerShell | `ssh amax` | 纯命令行 |
| 执行单条命令 | `ssh amax "cd /data1/yxy/projects/d2l_pytorch_labs && ls"` | 不进入交互式 shell |

### 1.2 本机 SSH 配置（已配好，存档备查）

`C:\Users\xlmn\.ssh\config`：

```
Host amax
  HostName 192.168.1.239
  User yxy
  IdentityFile C:/Users/xlmn/.ssh/id_ed25519
  ServerAliveInterval 60
  ServerAliveCountMax 3
```

- 公钥已写入服务器 `~/.ssh/authorized_keys`，无需密码
- **连接时一律用 `amax`，不要用 IP 地址**（IP 条目没有写 `User`，会用 Windows 用户名 `xlmn` 去登，报 `Permission denied`）

### 1.3 判断自己在哪台机器上

| 提示符 | 位置 |
|---|---|
| `PS C:\...>` 或 `C:\Users\xlmn>` | 本机 Windows |
| `yxy@amax:~$` | 服务器 |

> **最常见错误**：把 `scp D:\...` 这种 Windows 路径贴到服务器 shell 里。看到 `yxy@amax` 就说明在服务器上，`D:` 盘不存在。

## 4. 图像分类实验（CIFAR-10）

### 4.1 四个模型的预期表现

| 模型 | `--model` | 参数量 | 经验准确率 | V100S 上 20 轮耗时 |
|---|---|---:|---|---|
| SmallCNN | `smallcnn` | 94,538 | 实测 **58.1%** | ~5 分钟 |
| AlexNetCIFAR | `alexnet` | 2,388,298 | 78%~85% | ~8 分钟 |
| VGG11CIFAR | `vgg11` | 9,488,266 | 82%~88% | ~12 分钟 |
| ResNet18 | `resnet18` | 11,173,962 | 90%~94% | ~8 分钟 |

> SmallCNN 的 58% 是**实测值**（2026-10-30，batch=128，lr=0.01，20 轮），低于经验区间 65~75%，属于模型容量限制而非环境问题。

### 4.2 标准命令

```bash
# 基线（验证流程能跑通）
python train_image.py --model smallcnn --epochs 20 --batch-size 128 \
    --workers 8 --device cuda:0 --run-dir /data1/yxy/runs/smallcnn

# 推荐主力模型
python train_image.py --model resnet18 --epochs 20 --batch-size 128 \
    --workers 8 --device cuda:0 --run-dir /data1/yxy/runs/resnet18

# 对比：不开数据增广
python train_image.py --model resnet18 --epochs 20 --batch-size 128 --no-augment \
    --workers 8 --device cuda:1 --run-dir /data1/yxy/runs/resnet18_noaug

# 对比：更大 batch（学习率同比放大）
python train_image.py --model resnet18 --epochs 20 --batch-size 256 --lr 0.02 \
    --workers 8 --device cuda:2 --run-dir /data1/yxy/runs/resnet18_bs256
```

### 4.3 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | `resnet18` | `smallcnn` / `alexnet` / `vgg11` / `resnet18` |
| `--variant` | `cifar` | `cifar`（32×32 适配版）/ `torchvision`（224×224 原生版） |
| `--epochs` | 20 | 轮数 |
| `--batch-size` | 64 | **服务器建议 128**（V100 32G 显存很宽裕） |
| `--lr` | 0.01 | SGD + momentum 0.9 + 余弦退火 |
| `--weight-decay` | 5e-4 | 权重衰减 |
| `--workers` | **0** | **服务器必须显式设 8**，默认 0 是为 Windows 保守设置，会饿死 GPU |
| `--device` | `auto` | `cuda:0` ~ `cuda:6` |
| `--amp` | 关 | **V100 上不要加**（Volta 无 BF16，fp16 对小 batch 不稳） |
| `--no-augment` | 关 | 关闭随机裁剪/翻转 |
| `--smoke` | 关 | 128/64/64 样本、1 轮，仅验证流程 |
| `--run-dir` | **必填** | 输出目录 |

### 4.4 扩展：迁移学习（torchvision 原生模型）

```bash
python train_image.py --model resnet18 --variant torchvision --pretrained \
    --freeze-backbone --batch-size 16 --lr 0.01 --epochs 5 \
    --workers 8 --device cuda:0 --run-dir /data1/yxy/runs/resnet18_transfer
```

- 首次运行会下载 ImageNet 权重（需联网）
- 结果是 **迁移学习**，利用了额外预训练数据，**不能**和从零训练的结果放在同一张表里排名

## 5. 文本分类实验（IMDB）

> **前置条件**：先执行 `python prepare_data.py --dataset imdb`

```bash
# BiLSTM
python train_text.py --model bilstm --epochs 8 --batch-size 64 --lr 0.001 \
    --workers 8 --device cuda:0 --run-dir /data1/yxy/runs/bilstm

# TextCNN
python train_text.py --model textcnn --epochs 8 --batch-size 64 --lr 0.001 \
    --workers 8 --device cuda:1 --run-dir /data1/yxy/runs/textcnn
```

**参数**：`--model`（`bilstm`/`textcnn`）、`--epochs`（默认 8）、`--batch-size`（默认 64）、
`--lr`（默认 0.001）、`--max-length`（默认 256）、`--max-vocab`（默认 20000）、`--min-freq`（默认 2）。

**注意**：
- IMDB 是**英文**任务，预测文本也必须是英文
- 词表只从训练集统计，未知词 `<unk>=1`、填充 `<pad>=0`
- `--amp` 同样**不建议**在 V100 上加

## 6. 生成模型实验（VAE / GAN）

> 前置条件同 CIFAR-10（`data/cifar10/` 已就位）

```bash
# VAE（30 轮）
python train_vae.py --epochs 30 --batch-size 128 --latent-dim 64 \
    --workers 8 --device cuda:0 --run-dir /data1/yxy/runs/vae

# DCGAN（50 轮）
python train_gan.py --epochs 50 --batch-size 128 --latent-dim 64 \
    --workers 8 --device cuda:1 --run-dir /data1/yxy/runs/gan
```

**VAE 参数**：`--latent-dim`（默认 64）、`--beta`（默认 1.0）、`--observation-std`（默认 0.1）、`--lr`（默认 0.001）、`--epochs`（默认 30）
**GAN 参数**：`--latent-dim`（默认 64）、`--lr`（默认 0.0002）、`--epochs`（默认 50）

**独立评估与生成**：

```bash
python evaluate_generative.py --run-dir /data1/yxy/runs/vae
python evaluate_generative.py --run-dir /data1/yxy/runs/gan

python generate.py --run-dir /data1/yxy/runs/vae --num-samples 64 --seed 2026
python generate.py --run-dir /data1/yxy/runs/gan --num-samples 64 --seed 2026
```

**重要认知**：
- VAE 的重构 PSNR 与 GAN 的判别器 loss **不能**放在一起当作生成质量排名
- GAN 的 D loss 不能用来判断哪一轮的 G 最好
- 生成模型不计算分类 accuracy
- 默认输出不覆盖已有图片，用 `--output 新路径.png` 指定

## 7. 一键脚本 run.sh（推荐）

项目根目录下的 `run.sh` 把所有常用操作封装好了，位于 `/data1/yxy/projects/d2l_pytorch_labs/run.sh`。

### 7.1 它替你做了什么

| 能力 | 说明 |
|---|---|
| 自动激活环境 | 直接调用 `/data1/yxy/env/d2l/bin/python`，不依赖 `conda activate` |
| 自动挑卡 | 读取 `nvidia-smi`，选**显存占用最低**的 GPU |
| 自动命名目录 | 如 `image_resnet18_1030_1402`，带时间戳，不会撞 `best.pt` 保护 |
| 后台运行 | 内部用 `nohup ... &`，SSH 断开不影响 |
| 日志集中 | 统一写入 `/data1/yxy/runs/logs/<名字>.log` |
| 带 `-u` | 日志实时刷新，不会因为缓冲看不见进度 |

### 7.2 常用命令

```bash
cd /data1/yxy/projects/d2l_pytorch_labs     # 不需要 conda activate

./run.sh env                 # 环境 + 7 张卡占用情况（开机先跑这个）
./run.sh list                # 列出所有可用任务名

./run.sh image resnet18      # 图像分类，默认 20 轮 / batch 128 / workers 8
./run.sh text bilstm         # 文本分类，默认 8 轮
./run.sh vae                 # VAE，默认 30 轮
./run.sh gan                 # GAN，默认 50 轮
```

### 7.3 任务与默认参数

| 任务 | 模型参数 | 默认命令 |
|---|---|---|
| `image` | `smallcnn` / `alexnet` / `vgg11` / `resnet18` | `--epochs 20 --batch-size 128 --workers 8` |
| `text` | `bilstm` / `textcnn` | `--epochs 8 --workers 8` |
| `vae` | （无需模型名） | `--epochs 30 --batch-size 128 --latent-dim 64` |
| `gan` | （无需模型名） | `--epochs 50 --batch-size 128 --latent-dim 64` |

### 7.4 覆盖默认参数

命令后面追加的任何参数，会**覆盖**脚本里的同名默认值：

```bash
./run.sh image vgg11 --epochs 30 --batch-size 64            # 改轮数和 batch
./run.sh image resnet18 --lr 0.005                          # 改学习率
./run.sh image resnet18 --no-augment                        # 关数据增广
./run.sh image resnet18 --run-dir /data1/yxy/runs/my_exp    # 自己指定目录
./run.sh image resnet18 --variant torchvision --pretrained --freeze-backbone   # 迁移学习
./run.sh vae --latent-dim 32 --beta 4                       # VAE 调参
./run.sh gan --epochs 100                                   # GAN 跑更久
```

**指定 GPU**（不用自动挑）：

```bash
GPU=3 ./run.sh image resnet18
```

## 7.1 手动启动方式（备用）

不想用脚本、或者要精细控制时，用原始命令。服务器**没有安装 tmux**，用 `nohup` 替代：

### 启动后台训练

```bash
conda activate d2l
cd /data1/yxy/projects/d2l_pytorch_labs
mkdir -p /data1/yxy/runs/logs

nohup python -u train_image.py --model resnet18 --epochs 20 --batch-size 128 \
    --workers 8 --device cuda:0 --run-dir /data1/yxy/runs/resnet18 \
    > /data1/yxy/runs/logs/resnet18.log 2>&1 &

echo "PID: $!"
```

- **`-u`** 必须有，否则日志有缓冲、看不到实时进度
- 记下输出的 PID，中断 SSH 训练也会继续

### 查看进度

```bash
tail -f /data1/yxy/runs/logs/resnet18.log       # 实时跟随，Ctrl+C 只是退出查看
grep "Epoch" /data1/yxy/runs/logs/resnet18.log | tail -5   # 只看最近几轮
ps -p <PID>                                      # 进程是否还活着
```

### 停止训练

```bash
kill <PID>                # 正常终止
kill -9 <PID>             # 强制（极少需要）
```

### 如果管理员装了 tmux

```bash
sudo apt install -y tmux
tmux new -s train                    # 新建会话
# 里面跑训练命令
# Ctrl+B 再按 D  → 脱离
tmux attach -t train                 # 回来看
tmux ls                              # 列出所有会话
```

## 8. 结果怎么看

### 8.1 训练过程的终端输出

```
{
  "device": "cuda:0",
  "sizes": { "train": 45000, "val": 5000, "test": 10000 },
  "parameters": { "total": 11173962, "trainable": 11173962 }
}
  batch 100/352, loss=2.2971, acc=0.1179        ← 每 100 个 batch 打一次
Epoch 1/20 train_loss=2.1739 train_acc=0.1780 val_acc=0.2376
...
Epoch 20/20 train_loss=1.1607 train_acc=0.5888 val_acc=0.5854
Test [full] n=10000 accuracy=0.5808 macro_f1=0.5781
```

**逐项解读**：

| 字段 | 含义 | 怎么看 |
|---|---|---|
| `sizes` | 训练/验证/测试样本数 | CIFAR-10 应为 45000/5000/10000 |
| `parameters` | 参数量 | 和上表对照，验证模型建对了 |
| `train_loss` | 训练集交叉熵 | 应持续下降 |
| `train_acc` | 训练集准确率 | 应持续上升 |
| `val_acc` | **验证集准确率** | 用来选最佳模型的那一个 |
| `Test [full]` | 官方测试集 | **唯一的最终结论**，训练时从不访问 |
| `test_scope` | `full`=完整测试集，`subset`=smoke 子集 | `subset` 不能当结论 |

**健康曲线特征**：

- ✅ `train_acc` 与 `val_acc` 同步上升，差距 < 5% → 正常收敛
- ⚠️ `train_acc` 远高于 `val_acc`（差 15%+）→ 过拟合，需加增广/正则/减轮数
- ❌ `val_acc` 长时间不涨（平台期）→ 学习率可能不合适
- ❌ loss 变 `NaN` → 学习率太大（脚本会主动抛 `FloatingPointError`）

### 8.2 每次运行的产物目录

`/data1/yxy/runs/<run-dir>/` 下：

| 文件 | 内容 | 用途 |
|---|---|---|
| `config.json` | 模型、超参数、PyTorch 版本 | 复现时对照参数 |
| `data_manifest.json` | 数据集、划分索引、预处理、随机种子 | 证明划分一致 |
| `history.csv` | 每轮 train/val 的 loss、acc、F1、耗时 | 可用 Excel 打开 |
| `best.pt` | 按**验证集准确率**选出的最佳权重 + epoch | 预测用这个 |
| `test_metrics.json` | 测试准确率、macro F1、各类 F1、混淆矩阵 | **最终结果** |
| `learning_curves.png` | loss / accuracy 双折线（train vs val） | 判断收敛是否健康 |
| `confusion_matrix.png` | 10×10 测试混淆矩阵 | 找哪两类容易混 |
| `vocab.json` | 仅文本实验，预测时复用 | 文本模型必需 |

**生成模型额外产物**：

| 文件 | 内容 |
|---|---|
| `best.pt`（VAE）/ `last.pt`（GAN） | 权重 |
| `previews/epoch_XXX.png` | 每轮固定噪声的生成格子图 |
| `previews/epoch_XXX_reconstruction.png`（VAE） | 上排原图、下排重构 |
| `test_samples.png` | 独立测试噪声生成图 |
| `test_reconstruction.png`（VAE） | 测试集重构对照 |

## 10. 常见报错速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `运行目录已有 best.pt，请使用新的 --run-dir，防止覆盖实验。` | **保护机制**，不是错误 | 换一个 `--run-dir` 名字，如 `runs/resnet18_v2` |
| `运行目录已有 last.pt` | GAN 同样有保护 | 同上 |
| `未检测到 CUDA。请安装匹配的 PyTorch，或使用 --device cpu。` | 装在 CPU 版 torch 或设备名写错 | `python -c "import torch;print(torch.cuda.is_available())"`；检查 `--device cuda:0` |
| `ModuleNotFoundError: No module named 'labkit'` | 不在项目根目录 | `cd /data1/yxy/projects/d2l_pytorch_labs` |
| `ModuleNotFoundError: No module named 'requests'` | 环境没激活 | `conda activate d2l` |
| `FileNotFoundError: .../data/cifar10/...` | 数据缺失 | `python prepare_data.py --dataset cifar10` |
| `FileNotFoundError: IMDB 数据不存在` | 没下 IMDB | `python prepare_data.py --dataset imdb`，或加 `--offline` 前先准备好 |
| `FloatingPointError: 损失出现 NaN/Inf` | 学习率太大 | 降低 `--lr`，或去掉 `--amp` |
| `ModuleNotFoundError: torchvision...::nms` | torch / torchvision 版本不配 | 按同一套版本重装 |
| GPU 利用率个位数 | `--workers` 太小 | 设 `--workers 8`（或 12） |
| `Could not resolve hostname d` | 把 Windows 路径贴到服务器执行 | 回本机 PowerShell 执行 `scp` |
| `Permission denied (publickey,password)` | VS Code 用 IP 连（缺 `User`） | 改用 `amax` 别名 |
| `UnpackFailed` / VS Code 连不上 | `/home` 磁盘满 | 见 11.2 |
| `./run.sh: 权限不够` | 没执行权限 | `chmod +x run.sh` |
| `./run.sh: /bin/bash^M: 解释器错误` | 文件是 Windows 换行符 | `sed -i 's/\r$//' run.sh`，或 VS Code 右下角改 **CRLF → LF** 再保存 |
| `./run.sh: 未知任务` | 任务名拼错 | `./run.sh list` 看可用任务名 |
| `找不到 Python 环境` | `/data1/yxy/env/d2l` 被删或改名 | 重建环境，见 README |
| `./run.sh logs xxx` 报"日志不存在" | 名字写错 | 用 `ls /data1/yxy/runs/logs/` 查实际名字 |

## 11. 资源与环境规则

### 11.1 GPU 使用礼仪

- 服务器 7 张 V100S 是**多人共用**的，用前先 `nvidia-smi` 看谁在占
- 用 `--device cuda:N` 明确指定一张，不要指望脚本自动挑
- 7 张卡都空时，优先用 0、1、2

### 11.2 磁盘规则（重要）

服务器 `/home` 只有 **2.2 GB 可用且已 100%**，而 `/data1` 有 **7.6 TB**：

| 位置 | 用途 | 禁止 |
|---|---|---|
| `/data1/yxy/` | 环境、代码、数据、所有输出 | — |
| `/home/yxy/` | 仅 `.ssh`、`.bashrc`、软链接 | **不要往这里写大文件** |

已做的重定向：

- `~/.vscode-server` → `/data1/yxy/.vscode-server`（软链接）
- pip 缓存 → `/data1/yxy/.cache/pip`（`~/.config/pip/pip.conf`）
- conda 包缓存 → `/data1/yxy/env/.conda_pkgs`

**检查命令**：

```bash
df -h /home /data1 | tail -2
```

**清理命令**（安全）：

```bash
conda activate d2l
pip cache purge
conda clean --all -y
```

> `/home` 写满会导致：自己的 VS Code Server 解压失败（`UnpackFailed`）、服务器上其他同学的 Jupyter 写不了文件。
