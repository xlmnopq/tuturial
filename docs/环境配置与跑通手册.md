### 4.4 数据准备

`data/` 下只有 `splits/` 进了仓库，数据集本体被 `.gitignore` 排除，克隆下来还得单独补。服务器实测：

- `www.cs.toronto.edu`（CIFAR-10 官方源）：可连（301 重定向）；
- `huggingface.co`：**DNS 解析超时**，`prepare_data.py --cifar-mirror` 走不通；
- `ai.stanford.edu`（IMDB 官方源）：**连接被拒绝**。

所以最省事的做法是从本机直接拷（局域网，约 1 分钟）：

```powershell
$base='D:\program\tuturial\tuturial\d2l_pytorch_labs\data'
$remote='/data1/yxy/projects/tuturial/tuturial/d2l_pytorch_labs/data'
scp -r "$base\cifar10\cifar-10-batches-py" "amax:$remote/cifar10/"
scp "$base\imdb\train.jsonl" "$base\imdb\test.jsonl" "amax:$remote/imdb/"
```

拷完服务器上的体积：`cifar10` 178M、`imdb` 65M。

> `data/splits/*.json` 是固定 seed 的数据划分（`cifar10_seed42.json` 575 KB + `imdb_seed42.json` 282 KB，共约 858 KB），**已纳入仓库**，`git pull` 会自动带下来，不用再拷。
> 对应的 `.gitignore` 写法是 `data/*` + `!data/splits/` + `!data/splits/**`（先排除目录内容、再反选 splits 目录及其子文件）。

```bash

# 图像分类（CIFAR-10）

# 文本情感（IMDB）

# 复测 / 预测
```

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `Permission denied (publickey)` 推 GitHub | 公钥没进账号，或加成了 Signing Key | 查 `https://github.com/xlmnopq.keys`；重加时选 Authentication Key |
| 服务器 `git pull` 报连不上 GitHub | 服务器到 github.com 不通（443/22 都超时） | 走局域网裸仓库：本机 `git push amax main`，服务器 `git pull` |
| `data/` 下只有 `splits/` | 数据集本体被 `.gitignore` 排除（体积大） | 从本机 scp cifar10 与 imdb，或 `prepare_data.py`（需能联网到官方源） |
| 本地 `python` 版本怪（3.14） | 命令走的是 WindowsApps 存根 | 用 `D:\APPstore\anaconda3\python.exe` |
| GPU OOM | 1060 只有 3 GB / 别把 V100 占满 | 本地减小 batch，服务器加 `--amp`、看 `nvidia-smi` |
| 训练结果与之前对不上 | 没用同一份划分，或改过 `--seed` | `data/splits/` 已在仓库里，先 `git pull` 再跑；需要新划分时显式指定 `--seed` |
| `node build.mjs` 报 module not found | 课件脚本 import 写死了原机器绝对路径 | 换机器需改 import 路径 |
