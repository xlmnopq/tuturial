## 1. VS Code 配置

文件：`C:\Users\xlmn\AppData\Roaming\Code\User\settings.json`（JSONC，可带注释）。

```jsonc
{
    "remote.SSH.remotePlatform": { "amax": "linux" },
    "files.autoSave": "afterDelay",
    "git.path": "D:\\APPstore\\Git\\Git\\bin\\git.exe",

    // ---- GitLens ----
    "gitlens.currentLine.enabled": true,
    "gitlens.currentLine.dateFormat": "YYYY-MM-DD HH:mm",
    "gitlens.currentLine.scrollable": false,
    "gitlens.hovers.enabled": true,
    "gitlens.hovers.currentLine.over": "annotation",
    "gitlens.blame.avatars": false,
    "gitlens.hovers.avatars": false,
    "gitlens.graph.avatars": false,
    "gitlens.codeLens.enabled": true,
    "gitlens.codeLens.scopes": ["document"],
    "gitlens.codeLens.authors.enabled": false,
    "gitlens.codeLens.recentChange.enabled": true,
    "gitlens.statusBar.enabled": true,
    "gitlens.defaultDateFormat": "YYYY-MM-DD HH:mm",
    "gitlens.views.repositories.enabled": true,
    "gitlens.views.repositories.autoRefresh": true,
    "gitlens.terminalLinks.enabled": true
}
```

要点：

- `git.path` 必须写反斜杠转义（`\\`），GitLens 复用这条路径，不再走系统 PATH；
- `remote.SSH.remotePlatform` 让 VS Code 知道 `amax` 是 Linux，首次连接不用手选平台；
- 头像三项关掉，因为头像源是 github.com / gitlab.com，国内常超时，会让 blame 卡顿；
- CodeLens 只保留文件级、关掉作者，默认的 `document,containers` 会给每个函数加一行，函数多的文件很乱；
- 改完执行 `Developer: Reload Window` 生效；
- 17 个 `gitlens.*` 键已与扩展 `eamodio.gitlens-19.5.0` 的 `package.json` 逐一比对，全部合法，不会出现“未知配置”黄线。
- GitLens 19.x 的部分高级功能（Launchpad、AI、多仓库 graph）需要 Pro 订阅，上面这些行内 blame / 悬停 / CodeLens / 文件历史免费版可用。

```bash

```

## 6. 日常同步

| 场景 | 命令 |
|---|---|
| 本地改完 | `git add -A` → `git commit -m "..."` → `git sync` |
| 服务器取最新 | `cd /data1/yxy/projects/tuturial && git pull` |
| 服务器改完 | `git commit -am "..."` → `git push`（推到裸仓库） |
| 拉回服务器上的提交 | 本地 `git pull amax`（不是 `git pull`，那走 GitHub），再 `git sync` |

`git sync` 是全局别名：`git push origin main && git push amax main`。撤销：`git config --global --unset alias.sync`。

## 7. 踩坑记录

| 现象 | 原因 | 处理 |
|---|---|---|
| `git add` 报 `.git/index.lock: Permission denied` | DSH 沙箱对工作区根目录有写入授权，但 `.git`、`tuturial/`、`.acl-recovery` 等子目录的 ACL 缺少沙箱授权项（根目录有 `S-1-4-*` 允许项，子目录只继承了 `D:\program` 的旧 ACL） | 写入 git 索引/对象的命令在“完全权限”下执行；长期修复需给这些目录补齐授权（DSH 权限修复脚本会备份并给回滚命令） |
| GitHub `Permission denied (publickey)`，但公钥看起来加过了 | 公钥没进 `xlmnopq` 账号：`https://github.com/xlmnopq.keys` 返回 200 但内容为空 | 确认浏览器登录账号是 `xlmnopq`、Key type 选 `Authentication Key`、指纹须为 `SHA256:UnrLUsiYF...` |
| 服务器 `git ls-remote https://github.com/...` 卡 133 秒 | 服务器到 github.com 的 443/22 都不通（无代理） | 服务器不走 GitHub，改走局域网裸仓库 |
| PowerShell 里远程命令里的中文括号报 `bash: 未预期的记号 "("` | 全角括号在传递过程中被转成半角，bash 当成语法符号 | 远程命令只用 ASCII，避免中文标点 |
| `/home` 只剩 2.2 GB | 系统盘 1.5 T 已用 1.4 T | 把仓库、数据、训练产物都放 `/data1/yxy`（7.6 T 可用） |
| 提交时警告 `LF will be replaced by CRLF` | Git for Windows 安装器在系统配置里设了 `core.autocrlf=true`（`D:/APPstore/Git/Git/etc/gitconfig`） | 无需处理：仓库内存 LF、工作区检出 CRLF；若要两边完全一致可改 `core.autocrlf=input` |
| `node build.mjs` 在别的机器报 module not found | 脚本 import 写死了原机器绝对路径（`C:/Users/jhg/.cache/codex-runtimes/...`） | 换机器前改路径，或把依赖换成 npm 包重写 |
